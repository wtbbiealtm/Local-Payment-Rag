# Local AI Documentation Assistant for Payment System

A local AI assistant for searching and explaining internal payment system documentation.

The project is implemented as an **n8n** workflow and uses **RAG (Retrieval-Augmented Generation)**: PDF documentation is loaded into the **Qdrant** vector database, embeddings are generated locally with **Ollama / `nomic-embed-text`**, and responses are generated by an AI Agent powered by **Qwen3 8B**. The assistant is instructed to answer questions only from the retrieved documentation and conversation history.

## GitHub Description

**Local RAG assistant for payment system documentation: PDF → Ollama embeddings → Qdrant → AI Agent powered by Qwen3 8B. No external LLM APIs required.**

## Features

- Accepts PDF documentation through an n8n form.
- Stores document embeddings in Qdrant.
- Splits documents into chunks before indexing.
- Generates embeddings locally with Ollama.
- Searches documentation semantically rather than relying only on exact keyword matches.
- Maintains short-term conversation history with Window Buffer Memory.
- Provides practical instructions in a step-by-step format.
- Handles “why” questions by searching not only for direct explanations, but also related constraints, exceptions, errors, and examples.
- Handles “what does X depend on?” questions by performing multiple searches with different formulations.
- Avoids inventing parameters, APIs, settings, errors, or procedures that are not present in the knowledge base.
- Marks logical deductions separately with `Conclusion:`.
- Includes a source such as `section N, page M` only when that information is actually available in the retrieved document data.

The workflow contains two main flows: **document indexing** and **question answering**. For retrieval, the agent uses a dedicated vector-store tool connected to the same `payment_docs` collection.

## Tech Stack

- **n8n** — workflow orchestration and AI workflow automation
- **Ollama** — local model runtime
- **Qwen3 8B** — chat model for answer generation
- **nomic-embed-text** — embedding model for semantic retrieval
- **Qdrant** — vector database
- **RAG** — retrieval + generation
- **PDF** — source documentation format

## How It Works

### 1. Upload Documentation

A user opens the n8n form and uploads a PDF. The form accepts one required `.pdf` file.

### 2. Indexing

The document is processed by the Default Data Loader and Recursive Character Text Splitter. The splitter is configured with `chunkOverlap = 150`. Embeddings are then generated with `nomic-embed-text:latest`, and the resulting vectors are stored in the `payment_docs` Qdrant collection.

### 3. Retrieval

When a chat message arrives, the AI Agent gets access to the `payment_docs_tool`. The tool performs semantic retrieval from Qdrant using the same embedding model.

### 4. Answer Generation

The `qwen3:8b` model generates the response using the retrieved document fragments and conversation history. The system instructions explicitly tell the agent not to invent information that is missing from the documentation.

### 5. Handling Complex Questions

For “why” questions, the agent should search not only for an exact mention of the reason, but also neighboring sections containing limitations, exceptions, errors, and examples.

For questions such as “what does X depend on?”, the agent should perform multiple searches using different formulations and combine the related findings into a list of dependencies.

## Requirements

Before running the project, you will need:

- an **n8n** instance;
- **Ollama** installed and accessible from n8n;
- the following Ollama models:
  - `qwen3:8b`
  - `nomic-embed-text:latest`
- a **Qdrant** instance;
- configured Ollama and Qdrant credentials in n8n.

## Setup

1. Import the JSON workflow into n8n.
2. Configure **Ollama** and **Qdrant** credentials.
3. Make sure `qwen3:8b` is available in Ollama.
4. Make sure `nomic-embed-text:latest` is available in Ollama.
5. Create or connect the Qdrant collection `payment_docs`.
6. Activate the workflow.
7. Upload a PDF through the documentation upload form.
8. After indexing is complete, send a question through the chat trigger.

> Do not commit credentials from the original workflow to a public repository. Keep secrets configured locally in n8n.

## Example Questions

Once documentation has been indexed, you can ask questions such as:

```text
Which parameter is responsible for ...?

Why does the operation fail when ...?

What does ... depend on?

How should I configure ...?
```

For practical questions, the assistant is instructed to provide step-by-step actions. When the required information is not present in the knowledge base, it should explicitly say that the documentation does not describe it instead of guessing.

## Why This Project?

A general-purpose LLM can produce a confident and plausible answer that is nevertheless incorrect when working with internal technical documentation.

This project separates knowledge retrieval from generation: first, the system searches the internal documentation, and only then does the model generate an answer based on the retrieved context. This makes it possible to build a more controlled internal assistant without sending the documentation to an external LLM API.

## Current Limitations

- Answer quality depends on the quality and completeness of the uploaded documentation.
- The workflow defines explicit assistant behavior, but there is no dedicated automated evaluation of retrieval and answer quality yet.
- The original workflow does not specify the chunk size, so this README intentionally does not claim a specific value.
- There is no separate reranking layer for retrieved fragments.
- There is no automated regression test suite for questions and answers.
- The project is designed for local deployment and requires n8n, Ollama, and Qdrant to be configured independently.

## Possible Improvements

- Add reranking for retrieved chunks.
- Add an evaluation dataset with reference answers.
- Log retrieval quality and failed queries.
- Add versioning for documentation indexes.
- Separate collections by product or environment.
- Display citations for the exact retrieved chunks in the chat UI.
- Automatically re-index new PDF versions.
- Provide a Docker Compose setup for quick local deployment.
